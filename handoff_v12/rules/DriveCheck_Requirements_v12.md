# DriveCheck 누적 요구사항 및 화면 전환 규칙

2026.11.10 · 디자인 기준 v12

차량에서 말로 위기를 알리고, 해당 상황의 다음 행동을 안내한 뒤, 차량과 휴대폰에 사건 기록을 남기는 서비스다. 현대 Pleos 공모전 시안의 기준 문서로 사용한다. 화면에 나온 사건·연락 상태·센서 이벤트는 시연 데이터다.

## 사건 진행 화면

대표 시연은 **위험 감지 → 상태 확인 → 119 연결 → 위치 안내 → 보호자 알림** 순서다. 상태 확인은 불명확한 상황에서만 한다. 119가 직접 요청되거나 명백한 위험에 해당하면 지원되는 119 경로를 바로 연다. 준비된 의료 정보가 필요해진 때 ‘의료 정보’를, 별도 경찰 신고가 필요한 때 ‘112 연결’을 같은 순서에 추가한다. 의료 정보가 당장 필요하면 보호자 발송보다 앞에 표시한다.

진행 화면은 우선 행동 순서다. 위치 조회와 보호자 알림은 병렬로 처리할 수 있으며, 실제 이력은 사건 ID 아래 발생 시각 순서로 남긴다. 다음 단계로 넘어가는 근거는 ‘119 연결’의 실제 연결 확인, ‘위치 안내’의 주소 표시 또는 승인된 회선에서의 발언 상태, ‘보호자 알림’의 서버 접수, ‘의료 정보’의 카드 표시 또는 승인된 전송 결과다. 상담원·보호자·의료팀이 수신했다는 사실은 해당 회신을 별도로 확인한다.

화면에는 현재 행동에 필요한 문구만 표시한다. 위치 안내에는 주소와 다음 행동을 둔다. 승인된 회선에서는 ‘통화에 주소 전달’을 제공한다. 보호자 알림은 취소 가능 시간에만 숫자와 취소를 보여준다. 미확인·실패·취소는 실제 다음 행동이 달라질 때 표시한다.

### 운전자 상태에 따라 갈리는 화면

| 확인한 상황 | 보여줄 장면 | 다음 행동과 기록 |
|---|---|---|
| 직접 119 요청 | PDF 06A | 상태 확인을 생략하고 지원되는 시스템 발신 경로를 연다. 전화 화면 열림과 연결을 분리한다. |
| 위험 정도를 판단할 정보가 부족함 | 04A–04B | 충돌 이벤트가 있을 때만 충돌 신호를 표시한다. 모호한 도움 요청은 상태 확인부터 시작한다. |
| 괜찮다는 응답이 왔고 지속 위험이나 활성 통화가 없음 | 04C | 위기 화면을 닫고 발생·확인 기록을 보관한다. 위험이 계속되면 해당 안내를 유지한다. |
| 첫 질문 또는 재확인에 답이 없음 | 04D → 05A | 한 번 더 확인한다. 이후에는 상태 미확인으로 대기하며 버튼, 명시적 요청, 새 위험 신호를 받는다. |
| 응답 가능한 운전자가 운전을 계속하기 어렵다고 말함 | 05B | 가능한 경우 안전 정차를 안내한다. 위급하거나 119를 요청하면 발신 경로를 연다. |
| 동승자가 운전자의 실제 반응 없음 또는 의식불명을 제보함 | 05C → 06B | 진술을 보존하고 큰 119를 우선한다. 119를 선택하면 발신 화면으로 이동한다. 확인되지 않은 의식 상태는 별도 미확인이다. |
| 제조사 긴급 정차·비상등 동작이 확인됨 | 11쪽 | 제조사 회신을 표시한다. 119와 위치 확인은 허용된 경로에서 별도로 진행한다. |
| 불이나 연기 신고 또는 확인 가능한 화재 경고 | 12쪽 | 차량 상태에 맞는 대피·정차 안내와 119를 우선한다. |

실제 환자의 반응이 없는 경우를 가정한 신고 경로는 국민안전24 지침을 참고했다. 앱 질문에 답이 없는 경우는 사용자 상태를 확인할 수 없는 별도 상태로 둔다. [국민안전24](https://www.safekorea.go.kr/safekorea-kor/acts/nacts/action-guide.do?category=cardiopulmonaryResuscitation)

PDF 2쪽의 흐름표와 각 화면 위의 `→ 번호`에서 해당 장면으로 이동한다. 실제 앱 화면은 상황과 행동에 필요한 문구를 표시하고, PDF의 장면 번호는 화면 전환 명세에 사용한다.

## 1. 확정한 사용 경험

| ID | 요구사항 |
|---|---|
| UX-01 | 차량 가로 16:9를 시안 기준으로 하고, 등록·기록 편집·보험 제출은 휴대폰 세로 화면을 우선한다. Pleos의 실제 앱 영역은 차종과 창 구성에 맞춘다. 한 칸 배치에서도 119와 음성 요청을 우선한다. |
| UX-02 | 위기 화면에서 지금 할 행동을 먼저 보여준다. 제목·보조 안내·버튼은 같은 왼쪽 기준선에 둔다. 음성 재시도와 안전 응답의 마이크·캐릭터는 오른쪽의 같은 시각 중심에 배치한다. 진행 줄에는 버튼과 배지를 두지 않는다. |
| UX-03 | 오른쪽에는 사건 순서, 왼쪽에는 현재 행동과 차량 그림을 표시한다. 충돌 신호는 작은 진한 삼각 경고 아이콘과 한 줄 제목으로 표시한다. 주차가 확인되면 제목의 밝기를 1.62초 주기로 완만하게 바꾸고 차량 주변 원을 확장한다. 주행, 주차 미확인, 모션 줄이기 상태에서는 정지 화면을 쓴다. |
| UX-04 | 첫 음성 대기 화면에는 ‘음성으로 요청하세요’, 캐릭터·파형, 예시 “119 전화”, 가능한 보조 요청을 표시한다. 예시와 요청은 따옴표를 사용하고 배경 도형 없이 여백으로 구분한다. 발화가 시작되면 예시 자리에 자막을 표시하고 그 위에 화자 추정 또는 ‘화자 미확인’을 한 줄로 둔다. 마이크가 열려 있을 때만 주황 점을 켠다. |
| UX-05 | 캐릭터는 처음 사용한 아이스 하늘색·라일락·파스텔 분홍 그라데이션을 유지한다. 둥근 떡 실루엣에 얕은 2.5D 볼륨, 보드라운 무광 표면, 더 넓게 흐려지는 테두리 블러, 또렷한 작은 눈과 입의 차분한 표정을 사용한다. |
| UX-06 | 주차 상태가 확인되면 입력 레벨에 따라 캐릭터와 그림자가 소폭 늘고 줄며 파형이 반응한다. 주행 중, 주차 여부 미확인, 모션 줄이기 설정에서는 캐릭터·파형을 고정하고 상태점과 자막으로 입력 상태를 표시한다. |
| UX-07 | 발화 전에는 짧은 예시, 발화 중에는 중간 결과, 완료 이벤트를 받으면 최종 문장을 표시한다. 예시는 “운전하는 엄마가…” → “운전하는 엄마가 대답을…” → “운전하는 엄마가 대답을 안 해요.”다. 중간 자막은 화면 표시용, 확정 자막은 별도 사건 기록용이다. |
| UX-08 | ‘119 전화’는 빨간색과 흰 글씨를 쓴다. 정차 후 연락 선택 화면에는 차 그림 대신 지름 254 디자인 단위의 원형 119를 둔다. 위기 진행의 왼쪽 아래에는 사각 119를 두고, 동승자의 반응 없음 제보 화면에는 큰 원형 119를 우선한다. 전화 아이콘, 버튼, ‘119 전화’ 음성 명령을 같은 경로로 연결한다. |
| UX-09 | 연락 선택에 기존 보호자·경찰·견인·보험사 컬러 그림을 한 장의 반투명 패널에 놓는다. 아래 문구는 “보호자 알림”, “112 전화”, “견인 연락”, “보험사 연락”으로 고정한다. 그림과 문구를 포함하는 하나의 터치 영역과 같은 음성 명령으로 연결한다. 안전 확인 전에는 견인·보험사 선택을 숨긴다. |
| UX-10 | 아이·고령자·말하기가 어려운 탑승자도 같은 목적을 달성한다. 짧은 문장과 큰 터치 영역을 쓰고, 아이 안내에는 119 연결과 말할 문장만 제공한다. 시각·음성·터치 중 하나가 불가능할 때 다른 입력 경로를 연다. |
| UX-11 | 안내 문구는 관측 근거와 지금 할 행동을 한눈에 구분한다. 보조 설명, 판단 기준, 데이터 출처, 화면 이동 규칙은 화면 아래 문서 메모에 둔다. |
| UX-12 | 사건 진행 목록에서 현재 줄 앞에 주황 점을 하나 둔다. 주차 확인 시 점 밝기가 1.46초 주기로 바뀌며 다음 단계로 점이 옮겨간다. 지나간 줄과 예정 줄은 글자 밝기로 구분한다. 주행 중, 주차 미확인, 모션 줄이기 상태에서는 점과 감지 원을 고정한다. 휴대폰은 같은 사건 ID와 순서를 표시한다. |
| UX-13 | 통화 보조 화면에는 상대 질문 하나와 짧은 답을 최대 세 개 둔다. ‘직접 말하기’는 차량에서 답변·통화 조작과 같은 줄의 첫 자리에 배치하고, 휴대폰에서는 답변 바로 아래에 같은 간격으로 배치한다. 기존 마이크 그림과 ‘직접 말하기’ 문구를 밝은 유리 버튼에 함께 표시한다. 실제 회선에 주소를 전달할 때 ‘주소 전달 중’을 표시한다. 주차가 확인되면 주소 문구와 현재 단계점의 밝기를 천천히 바꾼다. |

## 2. 기능 요구사항

| ID | 요구사항 |
|---|---|
| FN-01 | 시작 입력은 명시적 음성·버튼 요청, 승인된 제조사 위험 신호, 동승자가 전한 상황이다. 충돌·에어백·주행 이상·운전자 미응답의 사용 여부는 대상 차량의 지원과 권한으로 결정한다. |
| FN-02 | ‘도와줘’처럼 불명확한 요청에는 상태를 묻는다. ‘119 전화’처럼 직접적인 요청이 들어오면 확인을 기다리지 않고 지원되는 전화 경로로 이어간다. 동승자가 실제로 운전자 반응이 없다고 제보하면 진술을 표시하고 119를 우선 제안한다. 진행 중인 공식 SOS가 확인되면 기존 경로를 표시한다. |
| FN-03 | 응답과 위험 신호를 별도로 기록한다. 괜찮다는 응답이 있고 지속 위험이나 활성 통화가 없으면 위기 화면을 닫는다. 첫 질문에 답이 없으면 한 번 더 확인하고 이후에는 상태 미확인으로 둔다. 단순 미응답은 의식불명, 자동 발신, 차량 제어를 확정하는 근거로 사용하지 않는다. 확인 간격은 실차 시험 후 정한다. |
| FN-04 | 보호자 동의로 주차 중 아이·동승자 음성을 녹음해 등록할 수 있다. 일치가 충분한 때만 ‘아동 동승자 · 추정’처럼 등록된 역할을 표시한다. 등록 없음, 낮은 유사도, 겹쳐 말함은 ‘화자 미확인’이다. 화자 표시는 긴급 전화 실행 조건이 아니다. |
| FN-05 | 화자 식별용 특징값은 차량에 암호화해 보관하는 안을 우선한다. 등록 원음은 처리 후 버리고, 휴대폰은 등록·삭제 상태를 표시한다. 별도 모델과 마이크 접근을 검증한다. 개인 식별용 특징은 민감정보로 다루고 별도 동의를 설계한다. 만 14세 미만 아동을 동의에 근거해 처리할 때 법정대리인 동의와 확인 절차를 둔다. |
| FN-06 | ‘119 전화’ 또는 버튼으로 지원되는 시스템 발신 경로를 호출한다. 이미 공식 SOS 또는 119 통화가 진행 중이면 같은 연결을 우선 표시한다. 전화 화면 열림·실제 연결·실패·미확인을 구분한다. 112는 별도 신고가 필요한 때, 견인·보험사는 안전 정차 뒤 제시한다. |
| FN-07 | 제조사 긴급 정차와 비상등 상태는 각각 최신 확인 결과를 표시한다. 점등 신호만 있으면 ‘비상등 켜짐’, 자동 작동 출처까지 확인하면 ‘비상등 자동 점등’으로 기록한다. 등록 차종·색상에 맞는 탑뷰를 사용하고 주차 상태가 확인될 때만 회전한다. 수동 비상등 버튼은 차량의 물리 버튼을 사용한다. |
| FN-08 | 등록·동의된 보호자에게 위치·사고 시각 등 동의된 항목을 보낸다. 준비와 발송은 긴급 전화·위치 조회를 기다리게 하지 않는다. 시연 카운트다운은 10초이며 음성 또는 터치 취소를 제공한다. 상위 대응 중에는 긴급 행동을 가리지 않는 범위에서 같은 행이나 연결 휴대폰에 취소 조작을 유지한다. 발송과 취소 중 하나만 확정하고 진술과 관측의 출처를 나눈다. |
| FN-09 | 네트워크가 끊기면 사건을 차량에 먼저 저장한다. 아직 유효한 미발송 건만 재시도하고 취소·만료 건은 사용자가 다시 선택한다. 서버 접수, 기기 전달 확인, 보호자 열람 확인은 실제 시각과 함께 기록한다. 발송 접수는 열람을 뜻하지 않는다. |
| FN-10 | 차량 상태와 사건 로그는 시간순으로 이어진다. 위치·갱신 시각, 가용한 직전 주행 기록·충돌·에어백·미응답, 음성 요청, 119 상태, 비상등·정차의 실제 결과, 보호자 전송·확인 상태를 출처별로 분리한다. 원본 이후의 사용자 정정은 별도 메모로 남긴다. |
| FN-11 | 보험사 전달은 안전 정차 뒤 휴대폰에서 같은 사건 ID를 열고 제출 항목을 검토해 PDF로 내보낸다. 시각·위치, 센서 관측, 차량 요청·회신, 전화·알림 결과가 기본이며 음성 자막은 기본 해제한다. 파일 준비·공유 요청·수신 확인은 각기 다른 상태다. 사본은 버전을 남긴다. |
| FN-12 | 보호자·견인·보험사 연락처를 각각 등록한다. 의료 카드에는 약물 알레르기, 복용약, 병원·진료과·전화, 필요한 메모를 사용자가 선택해 입력한다. 의료 정보와 화자 특징값은 자동 알림과 보험 제출 기본 범위에서 분리한다. |
| FN-13 | 사건 음성은 인식에 사용하고 확정 자막만 별도 저장하는 안을 기본으로 한다. 전화 경로가 마이크를 인수하면 일반 앱 인식은 종료한다. 승인된 통화 내 명령 채널에서만 전달·직접 말하기 명령을 처리한다. 통화 상대방 원음과 회선 오디오는 저장하지 않는다. 자막 정정·내보내기·삭제 범위는 휴대폰에서 확인한다. |
| FN-14 | 위치는 신고와 병렬로 확인한다. 119 연결 후 최신 주소를 표시한다. 승인된 회선과 명시적인 음성·터치 요청이 있으면 AI가 같은 통화에서 상황요원에게 주소를 말한다. ‘직접 말하기’를 선택하면 AI 발언만 멈춘다. 오래된 위치는 확인 시각을 표시한다. |
| FN-15 | 동승자가 운전자 무응답을 직접 알리면 ‘운전자 상태 확인 필요’와 진술 출처를 전달한다. ‘기절한 것 같아요’는 해당 발언이 실제로 들어온 경우에만 진술로 표시하며 의식 상태를 미확인으로 둔다. 아이 목소리만으로 운전불능을 판단하지 않는다. |
| FN-16 | 필요한 상황에서 의료 카드 열기를 제시한다. 승인된 전송 경로와 확인된 수신 기관이 있으면 선택한 알레르기·복용약 등 필요한 정보를 동의 또는 적용 가능한 근거로 전달한다. 수신 여부는 확인 신호가 있을 때 기록한다. 보호자와 보험사에 보내는 정보는 별도 범위다. |
| FN-17 | 승인된 통화에서 사용자가 ‘대신 답하기’를 선택하면 상대 질문을 자막으로 한 번에 하나 보여준다. 제안한 버튼은 누른 답만 같은 회선에서 음성으로 전달한다. 119와 지원되는 일반 통화에 적용한다. 직접 말하기로 돌아가면 합성 음성을 멈추고 기존 통화를 유지한다. |
| FN-18 | 자동 답변은 사용자가 명시적으로 켠 해당 통화에 적용한다. 최신 위치와 확인 가능한 차량 상태처럼 공유 범위에 든 데이터만 답한다. 부상·의식 여부는 탑승자가 답을 고르게 한다. 응답이 없으면 승인된 119 자동 모드에서 미확인 사실을 한 번 전달하고 기다린다. 일반 통화는 선택 답변을 기본으로 한다. |

## 3. 데이터와 판단 기준

아래 식별자는 앱 내부 분류를 설명하기 위한 이름이다. 실차에서는 승인된 차종별 이벤트·상태만 매핑한다. 사고·과열·정차·연결의 화면 예시는 가상 데이터로 표시한다.

| 기준 ID | 입력과 판단 | 표시할 결과 |
|---|---|---|
| R-01 위험 출처 | 제조사 승인 이벤트, 사용자 발화, 센서 관측값을 분리한다. 수신 시각·관측 시각·갱신 여부와 출처를 저장한다. | ‘충돌 신호 수신’, ‘사용자 연기 신고’, ‘정차 상태 확인’처럼 출처별로 표시한다. |
| R-02 화재 의심 | 제조사가 해당 모델에서 정의한 대피·화재 경고 또는 명시적인 불·연기 신고가 들어오면 화재 의심으로 처리한다. ‘연기가 없어요’처럼 부정된 문장과 안내 음성의 반향은 신고로 처리하지 않는다. | 화재 가이드와 119 경로를 먼저 띄운다. |
| R-03 과열 경고 | 고전압 배터리 과열 경고만 들어오면 해당 차종 매뉴얼의 안전 정차 안내에 매핑한다. 과열과 명시적인 연기 신고가 함께 들어오면 R-02가 우선한다. | 과열 경고에는 안전 정차. 연기까지 들어오면 주행·정차 상태별 화재 가이드. |
| R-04 이동 상태 | 최신 제조사 정차 회신을 우선한다. 속도만 제공되는 경우에는 대상 차종에서 검증한 속도·기어 또는 주차 상태 조합으로만 정차를 판단한다. 0 km/h 단일 샘플이나 오래된 상태값은 미확인이다. | 주행 중에는 안전 정차 안내. 정차 확인 후에는 주변을 살피고 차량에서 떨어지는 안내. 미확인에서는 두 경우의 조건부 안내. |
| R-05 위험 시간 | 최초 신호 수신에서 현재까지의 실제 경과를 단조 시계로 계산한다. 센서에서 찍힌 시각이 있으면 별도 저장한다. 예시 ‘경고 수신 후 12초’는 시연 값이다. | 수신 경과와 위치 갱신 시각만 표시한다. 폭발·발화까지 남은 시간과 임의 위험 확률을 계산하지 않는다. |
| R-06 발화 판단 | 완료된 ASR 문장과 현재 대화의 활성 제안을 사용한다. 중간 자막, 화자 유사도, 단순 무응답은 단독으로 제어·발송 근거가 되지 않는다. | 모호하거나 인식에 실패하면 한 번 다시 요청하고 터치·시스템 SOS 경로를 남긴다. |
| R-07 우선순위 | 위급한 경우 직접 119·공식 SOS, 진행 중인 구조 전화·즉시 대피, 통화에 필요한 위치와 상황을 앞세운다. 일반 확인은 애매한 신호에만 적용한다. 보호자 발송은 독립적으로 진행하고, 의료 카드·112는 필요해진 때 추가한다. | 긴급 안내를 유지하고, 조건부 행은 필요한 때만 추가한다. 건너뛴 행은 표시하지 않는다. 병렬 처리 결과는 실제 시각으로 기록한다. |
| R-08 통화 내 주소 전달 | 통화 연결, 최신 위치·주소, 승인된 송화 경로와 명시적 음성·터치를 확인한다. 오래된 위치는 마지막 확인 시각을 표시한다. | 같은 회선으로 합성 발언을 전달한다. 직접 말하기, 통화 종료, 채널 오류가 발생하면 합성 발언을 즉시 멈춘다. 발언 완료와 상황요원 수신 확인은 구분한다. |
| R-09 동승자 진술 | 화자 매칭과 발언 내용, 차량 미응답 신호를 분리한다. 아동의 운전자 무응답 진술은 안전 확인이 필요하다는 근거로 전달할 수 있다. | 역할은 ‘추정’ 또는 ‘미확인’, 운전자 의식은 확인 정보가 없으면 미확인. 화자 원음·특징값은 자동 전송하지 않는다. |
| R-10 통화 질문과 답변 | 현재 회선과 통화 차례를 확인하고 상대의 확정 자막으로 선택지를 만든다. 인식이 모호하면 답변을 보류하고 질문 반복 또는 직접 말하기를 안내한다. 같은 차례에서 승인한 문장만 한 번 발언한다. | 질문, 선택한 답, 발언 상태를 구분한다. AI 자동 발언은 사용자의 진술로 저장하지 않는다. |

## 4. 화면 전환과 빠졌던 상태

| 화면 | 진입 조건 | 다음 화면 |
|---|---|---|
| S-01 위험 감지 / 첫 화면 | 지원되는 위험 신호 수신 또는 사용자가 위기 도움 열기 | 신호 수신 때만 출처를 표시. 음성 입력, 119 직접 연결, 동승자 도움, 응답 확인 |
| S-02 음성 입력 | 말하기 시작 또는 지원되는 음성 호출 | 음성 요청 안내·예시·보조 요청 → 발화가 들어오면 중간 자막 → 완료. 직접 119, 연기 신고, 상태 확인, 제안 응답 등으로 분기 |
| S-03 인식 실패 | 음성 권한 불가, 낮은 신뢰도, 또는 무음으로 입력 종료 | 음성 재시도 또는 큰 119 터치. 위험 신호에 따라 직전 안내를 유지 |
| S-04 안전 확인 | 사용자가 괜찮다고 답하고 지속 위험이나 활성 통화가 없음 | 위기 화면 종료. 발생·확인 기록은 보관 |
| S-05 동승자 도움 | 동승자의 구체적 요청 또는 미응답과 확인 가능한 위험 신호 | 아이가 읽거나 말할 119 문장, 직접 119. 차량 조작은 제조사 경로 |
| S-06 119 제안 | 구조가 필요한 진술 또는 위험 상황 | 음성 ‘119 전화’ 또는 터치로 지원되는 시스템 발신 경로를 연다. 위치 확인을 병렬로 시작하고 실제 연결을 기다린다. |
| S-07 전화 화면 열림 | 지원되는 시스템 전화 경로를 호출 | 119 연결 행을 유지한다. 실제 연결 회신이 오면 위치 안내로 가고, 실패나 회신 없음은 그 상태로 표시한다. |
| S-08 통화 / 실패 | 시스템이 연결 또는 실패를 회신 | 연결 후에는 위치 안내, 실패 시에는 휴대폰 119나 지원 차량의 공식 SOS를 안내한다. |
| S-09 제조사 긴급 정차와 자동 비상등 | 지원 차량의 최신 제조사 안전 기능 상태 | 작동 확인 → 감속 → 정차 확인 → 비상등 자동 점등 확인. 상태를 알 수 없으면 확인 중/미확인 표시 및 119 유지 |
| S-10 과열 / 화재 | R-02 또는 R-03 | 주행, 정차 확인, 정차 미확인으로 분기. 직접 119는 별도 연결 |
| S-11 다른 상황 가이드 | 운전 곤란, 충돌 부상, 안전 정차 후 고장 | 119 또는 견인. 위험과 부상 여부에 따라 안내 내용을 바꾼다 |
| S-12 자동 보호자 알림 | 보호자 옵션 선택 또는 사전 동의된 위험 조건 | 같은 사건 행에 카운트다운과 취소. 발송·취소·미발송은 실제 결과로 반영하고 열람은 사건 기록에 남김 |
| S-13 다른 연락처 | 별도 경찰 신고 필요 또는 견인·보험사 연락 요청 | 112가 필요하면 사건 순서에 추가. 진행 중인 119를 유지하고 공동 대응 결과는 확인된 때 반영. 견인·보험사는 안전 확인 뒤 전화 |
| S-14 사건 기록 | 안전한 정차 이후 상세 열기 | 차량 기록, 별도 자막, 휴대폰 이어보기. 휴대폰 연결이 없으면 연결 안내와 로컬 보관 |
| S-15 휴대폰 검토 / 공유 | 승인된 소유자가 사건 열기 | 정정 메모 → 제출 항목 → 파일 준비 → 공유 요청 → 확인 가능한 수신 상태 |
| S-16 사전 설정 | 보호자가 안전한 상황에 설정 열기 | 연락처·의료 카드·선택 화자 등록, 등록과 삭제 결과 표시 |
| S-17 좁은 차량 앱 창 | Pleos 앱 영역 한 칸 표시 | 주요 음성 예시와 119를 앞에 배치. 상세 기록은 넓은 화면이나 휴대폰으로 이어보기 |
| S-18 119 위치 안내 | 실제 연결이 확인됨 | 최신 주소를 표시한다. 승인된 경로에서 ‘주소 말해 줘’나 ‘통화에 주소 전달’ 입력 시 AI 발언으로 전환한다. ‘직접 말하기’로 기존 통화에서 사용자 발언을 이어간다. 연동 미지원 시 주소를 보고 직접 말한다. |
| S-19 동승자 신고 전달 | 명시적인 운전자 이상 진술 또는 검증된 관측 | 진술과 관측을 구분해 상태 확인 요청을 보여준다. 자동 알림의 조건과 취소 절차는 별도 적용 |
| S-20 보험사 제출 | 사용자가 파일을 만들고 목적지를 선택 | 사후 화면에 파일과 공유 동작을 표시. 수신은 확인 신호가 있는 때만 같은 화면 한 줄과 사건 기록에 반영 |
| S-21 의료 정보 | 구급대가 필요로 하거나 사용자가 요청 | 같은 사건 순서에 의료 정보 행 추가. 카드 열기 또는 승인된 수신 기관과 항목 확인 뒤 전송 |
| S-22 대신 답하기 | 실제 통화 연결, 승인된 자막·음성 경로, 사용자의 시작 요청 | 답변 고르기 또는 자동 답변 켜기. 상대 질문에 맞는 선택지만 표시한다. |

## 5. 화면 디자인 원칙

- 차량은 1,200×675 기준에 부드러운 회청색 반투명 배경 한 겹을 사용한다. 연락판은 뒤 배경을 흐려 약하게 비추고 그림과 글자는 선명하게 유지한다. 휴대폰은 흰색 `#FFFFFF`를 쓰고 등록 차량의 큰 탑뷰 옆에 위치·의료 카드·긴급 연락을 세로 유리 버튼으로 둔다. 사건은 같은 ID로 아래에서 이어본다. 차량 배경은 세 번째 레퍼런스, 휴대폰 배치는 첫 번째와 두 번째 레퍼런스를 반영한다.
- 차량의 제목·조작 기준선은 왼쪽 88, 진행 줄 간격은 64 디자인 단위다. 위험 감지 그림의 배치 폭은 464 단위다. 같은 글꼴 Asta Sans를 쓰고 한글 기본 자간, 4단위 줄 간격, 고정폭 카운트다운 숫자를 사용한다. 충돌 제목 40, 일반 제목 48–56, 진행 줄 32, 본문 기본 24 단위로 잡는다. 현재·지난·예정 단계의 글자 불투명도는 100%·80%·67%다. ### 후속 수정에도 적용하는 화면 기준

## 6. 연결된 통화에서 대신 답하기

### 119 통화

| 상태 | 화면과 입력 | 작동과 기록 |
|---|---|---|
| 발신 | ‘119 전화’ 또는 전화 버튼 | 지원되는 시스템 긴급전화 경로를 연다. 전화 화면 열림과 연결 확인은 따로 기록한다. |
| 주소 전달 | 승인된 회선에서 ‘주소 말해 줘’ 또는 ‘통화에 주소 전달’ 선택 | 최신 주소를 확인해 같은 통화에서 말한다. 말하는 동안 ‘주소 전달 중’을 표시하고, 주차 확인 때에만 그 글자의 밝기를 바꾼다. |
| 대화 보조 | ‘대신 답하기’에서 답변 고르기 또는 자동 답변 켜기 | 활성 회선에서 상대의 질문을 받아 한 개씩 표시한다. 자동 답변은 해당 통화에 명시적으로 켜고, 최신 주소나 확인된 차량 신호만 사용한다. 첫 합성 발언은 AI 대화 보조임을 알린다. |
| 답변 선택 | ‘다친 사람이 있나요?’ → ‘있어요’, ‘없어요’, ‘잘 모르겠어요’ | 선택한 답을 맥락에 맞는 문장으로 바꾸어 실제 통화 상대에게 음성으로 전달한다. 발언 중에는 전달 문장을 보여준다. |
| 사용자 응답 미확인 | 자동 답변이 켜진 통화에서 질문 이후 응답이 확인되지 않음 | ‘현재 탑승자 답변을 확인하지 못했습니다’라고 한 차례 알린다. 부상이나 의식 상태는 확인되지 않은 값으로 둔다. |
| 직접 말하기 | 같은 자리의 ‘직접 말하기’ | AI 발언을 즉시 중단하고 기존 통화를 이어간다. 승인된 명령 채널에서는 음성으로도 이 동작을 요청할 수 있다. |

### 보호자와 일반 전화

승인된 일반 통화에서도 상대 질문을 보고 고른 답을 같은 전화에서 음성으로 전달한다. 예를 들어 ‘지금 뭐가 필요해?’에 ‘지금 와 줘’, ‘전화 끊지 마’, ‘괜찮아’를 제시한다. 가족·보호자 외의 일반 통화에는 사용자가 해당 통화에서 켰을 때 적용한다. 차량과 휴대폰은 같은 선택지를 쓰고 ‘직접 말하기’를 유지한다. 위치와 의료 정보에는 수신 대상별 공유 동의를 확인한다.

### 데이터와 예외

- 통화 ID와 차례 ID를 기준으로 중복 발언을 막는다. 상대의 최종 자막, 선택된 답, 검증된 자동 응답에 각각 출처를 붙인다. 타임라인에는 사용자가 선택한 답과 앱의 자동 발언, 요청·회선 전달·수신 확인을 구분한다. 저장 동의 범위 안에서 승인된 사건 데이터만 남기고 통화 원음은 보관하지 않는다.
- 잘못 인식했거나 질문을 분류할 수 없으면 AI 답변을 보류한다. 상대에게 한 번 다시 묻거나 직접 말하기를 제공한다. 통화 연결이 끊기거나 음성 경로가 실패하면 발언을 중지한다. 연결이나 위치가 확인되지 않으면 해당 상태만 표시한다.
- 주행 중 운전자에게 화면 응답을 강제하지 않는다. 사용자 역할과 차량 앱 제약에 따라 동승자 조작과 승인된 음성 명령 경로를 우선한다. 자동 답변 권한은 통화 종료와 함께 해제한다.
- 주소 텍스트는 승인된 전송 경로가 확인되면 제공한다. 소방청 다매체 119 문자 신고는 별도 채널이다. [소방청 119 다매체 신고](https://www.nfa.go.kr/nfa/news/pressrelease/press/?cntId=2097&mode=view&pageIdx=2&searchCondition=all)

일부 Android 휴대폰의 Live Caption은 상대 질문을 자막으로 보여주고 사용자가 입력한 답을 음성으로 읽는다. Apple은 활성 통화에 합성 음성을 보내는 접근성 예제를 제공한다. DriveCheck의 시안은 그 입력을 질문에 맞는 큰 선택지로 바꾼다. 공개 Pleos TTS의 차량 스피커 재생과 119 회선의 음성 전달은 별도다. 긴급 통화 자막·발언 제어는 제조사·플랫폼·신고기관 연동을 검증한 경로에서 시연한다. 공모전 화면의 통화와 AI 발언은 가상 데이터다. [Apple 충돌 감지](https://support.apple.com/guide/iphone/manage-crash-detection-iph948a628e9/ios) · [Android Telecom](https://developer.android.com/develop/connectivity/telecom/dialer-app) · [Pleos TextToSpeech](https://document.pleos.ai/en/docs/pleos-only/connect-sdk-pleos/TextToSpeech/intro)
- 소방청의 119안심콜은 사전 등록 정보를 구급대가 활용하는 별도 사례다. 이 시안의 의료팀 전송 화면은 승인된 기관 연동을 전제로 하며, 건강 정보와 화자 등록 특징값은 권한과 보관 범위를 각각 확인한다. [소방청 119안심콜](https://www.nfa.go.kr/nfa/safetyinfo/emergencyservice/urelaxcallservice/) · [개인정보 보호법 제23조](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029927029)
- 구급 신고에서는 확인한 위치와 환자 상태를 설명하고 상황요원의 안내를 따른다. 긴급 기관의 신고 이관과 공동 대응 결과는 확인된 때 반영한다. [행정안전부 119 신고 안내](https://www.mois.go.kr/chd/sub/a06/rescue/screen.do) · [긴급신고 통합서비스](https://www.mois.go.kr/frt/sub/a06/b10/emergencycall/screen.do)
